# Приёмочные проверки Subject-01

Статус: **план проверок, не результаты тестов**.
Связанный договор: [SUBJECT_CONTRACT.md](SUBJECT_CONTRACT.md).
Все эксперименты до рождения выполняются на диагностических состояниях.

| ID | Проверка | Наблюдаемый критерий |
| --- | --- | --- |
| C01 | Возобновление | После штатной остановки состояние совпадает, а следующие 1000 шагов с теми же воздействиями дают те же хеши; включены оба обучаемых слоя, гипотезы, память, RNG. |
| C02 | Авария записи | Прерывание до/после каждой границы транзакции не создаёт смешанное состояние; восстановлен последний подтверждённый тик, повтор команды не применяется дважды. |
| C03 | Один писатель | Второй процесс на тот же каталог получает отказ; после штатного завершения первый запуск возобновляется. Отдельно проверены Windows и Linux; распределённая гарантия не заявляется. |
| C04 | Пауза | Сдвиг реальных часов на сутки не меняет следующий тик, память и состояние организма; закрытие UI при работающем процессе не останавливает тики. |
| C05 | Консолидация | Выбранная организмом запись сохраняется после перезапуска; вытеснение временного опыта не удаляет консолидированное. Отбор не зависит от недоступных внешних меток. |
| C06 | Защита | Обычный ущерб, перестройка и попытка обычного API удалить защищённое не меняют его контрольную сумму; потеря пути извлечения отличается от уничтожения содержания. |
| C07 | Пересмотр | На противоречащем опыте текущий вывод меняется, исходное воспоминание сохраняется; наличие всех прежних убеждений не требуется. |
| C08 | Исключение | Без отдельного подтверждения запись ядра отклонена; подтверждение привязано к конкретной цели, истекает и не переиспользуется; действие и последствия отражены в аудите. |
| C09 | Нет служебного знания | Обоим слоям доступны только разрешённые каналы; изменение скрытых ID/меток при одинаковых сигналах не меняет их результат. |
| C10 | Отсутствие карты тела | Переименование/перестановка диагностических каналов не открывает семантический справочник; освоение причинных связей сравнивается с необучающимся контролем на заранее заданных пробах. |
| C11 | Границы тела | Допустимые адаптации проходят; попытка добавить новую конечность или орган отвергается исполнителем. Цена перестройки измеряется отдельно от оценки исследователя. |
| C12 | Общий опыт | Оба слоя получают один доступный поток, имеют раздельные состояния моделей; готовый вывод исследователя не записывается напрямую в MainController. |
| C13 | Только предложения | Исследователь не может напрямую вызвать моторный исполнитель; каждый реальный моторный вектор имеет единственное решение арбитра. |
| C14 | Причинное обучение | Изменение действия влияет на предсказанные последствия; точность оценивается на новых пробах и сравнивается с замороженным предиктором, а не только на обучающем буфере. |
| C15 | Проверка на модели | Гипотеза не вызывает реальных изменений до probation; внутренний прогноз не обращается к WorldCore или привилегированному телу. |
| C16 | Ошибка прогноза | Намеренно неверная внутренняя модель приводит к измеримому расхождению; ограниченная проба прекращается по объявленным условиям, опыт сохраняется. |
| C17 | Обратимость | Коррекция параметра идёт новым событием; структурная компенсация расходует время/ресурсы; тик и память не откатываются. |
| C18 | Обучение методов | Меняется хотя бы один разрешённый метод выбора/проверки кандидатов; эффект оценён на новых задачах против фиксированного метода. Критерии успеха, seeds и пороги зафиксированы до эксперимента. |
| C19 | Восстановление | Тяжёлое виртуальное повреждение не стирает ядро/память; восстановление при явно заданном минимальном ресурсе идёт вперёд с тем же origin_id, без загрузки старого организма. |
| C20 | Нет скрытого ресурса | Энергия и материал ремонта сходятся с балансом мира; защищённый минимум учитывается как явный закон, не тайная команда наблюдателя. |
| C21 | Телеметрия | Каждый показываемый сигнал/рост/проба соответствует вычисленному событию; мысленный и реальный результат различимы; потеря онлайн-пакетов не маскируется анимацией. |
| C22 | Допуск к рождению | Есть отчёт C01–C21, проверенные бюджеты, начальный контракт, хеши кода/законов и явное решение владельца. Диагностические состояния не переименовываются в официальную жизнь. |

## Правила оценки

- Цифра 1000 в C01 — предложенный минимальный инженерный прогон, не выбранный
  владельцем закон мира. Дополнить нагрузочными проверками до рождения.
- Сравнения C10/C14/C18 проводить на наборе заранее выбранных seeds и вмешательств,
  фиксируя эффект, разброс и неудачи. Пороги утвердить до просмотра результата;
  подобрать критерий постфактум под красивый граф нельзя.
- Для C18 разрешены проверки отдельных моделей/алгоритмов, не параллельные
  официальные существа.
- Не все критерии проверяются unit-тестом: для обучения нужен воспроизводимый
  экспериментальный отчёт. Непройденный исследовательский критерий не обходится
  новым названием компонента.
- Проверки на повреждение работают с тестовыми каталогами, не с официальной памятью.
- Проверки из существующего CI подтверждают диагностический прототип, а не C01–C22
  автоматически. Данный коммит не добавляет реализацию новых механизмов.

## Первый исполнимый пакет работ: A

1. Ввести отдельный формат состояния непрерывности с schema_version, origin_id,
   subject_id, tick, command_seq и полным сериализованным диагностическим состоянием.
2. Реализовать транзакционную фиксацию принятой команды и подтверждённого тика,
   проверку целостности и recovery до последней подтверждённой записи.
3. Добавить владение каталогом одним процессом; несовместимое состояние не
   пересоздавать и не удалять.
4. Отделить подтверждённую телеметрию от незавершённого вычисления.
5. Добавить fault-injection, проверку двойного запуска, повторной команды,
   заполнения диска и продолжения после паузы.
6. Зафиксировать измеренную потерю/задержку при сбоях и границы гарантии,
   не заявляя защиты от уничтожения всех носителей.
