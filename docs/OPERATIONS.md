# Запуск и хранение Subject-01

## Первый запуск на Windows

1. Установить Python 3.11 или новее. Распаковать сборку целиком в постоянную папку.
2. Дважды нажать `start-subject.bat`.
3. Нажать Enter, чтобы посмотреть тестовую среду. Её история не станет официальной жизнью.
4. Для первого рождения после чтения отчёта выбрать `1`. Программа проверит допуск
   именно установленного кода, покажет последствия и точную фразу подтверждения.
5. Ввести фразу только если решение о первом рождении принято. Последующие запуски
   автоматически продолжают зарегистрированную жизнь; повторного рождения нет.

На Linux/macOS: `sh start-subject.sh`. Продвинутый запуск наблюдателя:
`PYTHONPATH=src python -m subject01.observer --candidate --port 8766`.
Официальное продолжение: `PYTHONPATH=src python -m subject01.observer --subject`.

Закрытие вкладки не выключает мир. Для остановки нажать Ctrl+C в окне Python.
Каждый завершённый шаг уже сохранён. Отключённое время не досчитывается.

## Единственная личность

Регистрация хранится в `~/.subject01/identity.json` в домашнем каталоге пользователя
ОС; состояние — в выбранной папке, по умолчанию `data-subject`. Не удалять регистрацию
и не запускать резервные копии как параллельные существа. Блокировка защищает
один каталог на одном компьютере, не произвольные вручную созданные копии на разных ПК.

Повтор подтверждения после сбоя завершает то же зарезервированное рождение.
Программа не переименовывает тестовую историю, не создаёт замену при потере данных
и не восстанавливает уничтоженное владельцем ядро. При потере регистрации или
накопителя остановиться и восстановить исходные файлы; не удалять остатки истории.

Обновление старого кандидата требует отдельной фразы `ОБНОВИТЬ КАНДИДАТ`:
личность и опыт сохраняются, смена кода записывается в журнал. Для официальной
жизни этот механизм запрещён; исполняемый код и законы закреплены при рождении.

## Память и наблюдение

В браузере доступны мир, сенсорная сеть и две модели прогноза, реальные сигналы,
пауза, выбранные воспоминания и вмешательства владельца. В полном состоянии
показаны первые 100 записей; кнопки памяти листают архив, ссылка выгружает всё
потоком JSONL. Выгрузка памяти соответствует одному снимку, даже если мир продолжает
работать. Большая выгрузка временно удерживает SQLite WAL: следить за местом на диске.

Правки тела, весов сети/моделей, защищённых воспоминаний и ядра требуют точного
подтверждения. Перед редактированием остановить мир кнопкой «Пауза», чтобы цель
не изменилась между просмотром и подтверждением. Новые значения задаются JSON;
параметры тела и числовых моделей доступны в полном состоянии. Добавленные
наблюдателем энергия и материал явно учитываются в ресурсном балансе.

## Перенос старого журнала на другой диск

Полный журнал сохраняет все события и продолжает расти. По измеренному прогону
ориентир — несколько гигабайт за сутки непрерывной работы; это проекция, не квота.
Можно сразу хранить данные на большом диске. Старые блоки журнала также можно
переносить отдельно; сами воспоминания и текущий мозг остаются в основной базе.

1. Остановить программу через Ctrl+C.
2. Выбрать постоянную папку на архивном диске. Её нельзя затем удалять или переименовывать.
3. Открыть терминал в папке проекта. На Windows PowerShell выполнить:

```powershell
$env:PYTHONPATH="src"
python -m subject01.continuity --offload-journal "data-subject" --destination "E:\Subject01-archives"
```

На Linux/macOS:

```bash
PYTHONPATH=src python -m subject01.continuity --offload-journal data-subject --destination /mnt/archive/subject01
```

4. Дождаться отчёта с путём `.pack`, числом блоков и байтами. Запустить Subject-01 снова.

Перенос сначала записывает и проверяет архивный файл, затем одной транзакцией
заменяет содержимое старых блоков ссылками. При сбое до фиксации исходные блоки
остаются в базе; может остаться лишний неподключённый `.pack`. Не удалять файлы
вслепую. После фиксации архивный диск обязателен для полного журнала и перезапуска.
Отсутствующий или обрезанный архив вызывает отказ, а не очистку истории.

Архивирование можно повторять: уже перенесённые блоки не копируются снова.
Файлы `.pack` — часть единой истории, **не резервная копия**. Резервировать следует
остановленную папку данных, все подключённые архивы и регистрацию личности вместе.
Проверки аварийного завершения процесса не гарантируют сохранность при физическом
уничтожении носителей или всех резервных копий.

## Бюджеты и техническая пауза

Активный кэш воспоминаний — максимум 128 записей. Индекс порядковых позиций
находится во временной дисковой таблице SQLite и восстанавливается из проверенных
записей при запуске. Проверка целостности при большом архиве занимает больше времени;
это не зависание и не попытка заменить организм.

При свободном месте менее 64 МиБ следующий шаг запрещён. Освободить место переносом
журналов или расширением накопителя, затем перезапустить программу. Не удалять
защищённые воспоминания для обхода ограничения. При ошибке фиксации всегда требуется
перезапуск: продолжать по неподтверждённому состоянию запрещено.

Целевой шаг мира — 50 мс. Проверяется средняя скорость; обычная ОС не гарантирует
каждый шаг ровно за 50 мс. Измерения сделаны в среде разработки и CI, не на ПК владельца.
Модель исследовательская: сознание, понимание речи и человеческая ходьба не заявляются.
